# Add games from a shelf photo

As a board game owner, I want to photograph a section of my game shelf so I can add several games to my library in one batch.

**Proposed beta target — one shelf section with 6–10 visible titles.** Start with six as the capture guidance and test 6, 10, 15 and 20 titles per photo. Set the published guidance and initial submit limit from real-device results. The photo can contain more boxes than the recommended capture size, so preserve detected overflow as drafts for a subsequent submit or let the user crop and rescan a smaller section.

## Capture and review

1. Add **Scan a shelf** to the Flutter library add menu. Let the user take a photo or choose one from Photos. Ask them to fill the frame with one shelf section and keep the titles visible. Offer a crop or retake when the image is too wide, blurry, or yields too few usable results.
2. Open **Review games** as soon as local recognition has proposed titles. Show a photo reference and a scrollable list in shelf order. Each row shows the detected title, an optional crop, and the proposed catalog game or a status such as **Looking up match**, **Needs review**, **No match**, or **Already in library**. Lookup results update as they arrive while the list remains editable.
3. For each row, let the user **Ignore** and undo, correct the read title, search again, choose another BoardGameGeek result, and preview the same game details as in single add. Keep the corrected search text in the draft when the user returns to the list. Provide **Add missing game** to search by title for a box the scanner skipped. Require the user to pick a game for ambiguous results. Mark already-owned games as complete.
4. Show **Add N games** with the number of entries selected and ready to save. Show how many rows still need review so a user can add the ready games or resolve more first. On submit, show what was added, what was already owned, and what needs retry. Keep failed drafts and their edits available for retry. Only selected, resolved rows create library entries.

The current Flutter single-add flow lets users edit their search, choose a catalog result and preview its details. Reuse that picker and preview with a draft return value for shelf review and the existing save action in single add. The selected BoardGameGeek ID determines the canonical name and metadata. [Single-game entry](../flutter_app/lib/features/library/manual_game_entry_page.dart)

## Implementation sequence

1. **Prototype extraction.** Reuse Apple Vision and Android ML Kit on-device, along with the existing line coordinates. The current extractor ranks the whole image by relative text height, can merge lines across adjacent boxes, and returns up to three alternatives for one box. In shelf mode, group spatially related lines into probable title regions first. Rank and clean candidate text inside each region so small spines can compete locally. Give each draft a stable ID and keep source bounds and OCR alternatives. Compare one full-frame pass at the current 2,000 px width with a higher bounded resolution and a bounded second pass on cropped sections using their original pixels. Test the iOS minimum text height and orientation handling on both platforms. [Scanner](../flutter_app/lib/features/scanner/scanner_screen.dart), [Title extractor](../flutter_app/lib/features/scanner/title_extractor.dart), [Apple Vision text height](https://developer.apple.com/documentation/vision/vnrecognizetextrequest/minimumtextheight), [ML Kit input guidelines](https://developers.google.com/ml-kit/vision/text-recognition/v2/android#input_image_guidelines)
2. **Resolve catalog matches progressively.** Check the shared catalog and cached search results first, then send deduplicated title queries through the existing server-side BoardGameGeek integration for misses. Use the same result ranking as single add as a starting point. Require a strong, unambiguous match to preselect a draft and invalidate the selection when its query changes. Use a server-side request budget and backoff, and load full details on demand for the preview. BoardGameGeek search takes one title query at a time. Its details endpoint accepts up to 20 known IDs per request, which can reduce enrichment calls for uncached confirmed games. [Games service](../flutter_app/lib/data/services/games_service.dart), [BoardGameGeek API usage](https://boardgamegeek.com/using_the_xml_api), [BoardGameGeek XML API2](https://boardgamegeek.com/wiki/page/BGG_XML_API2)
3. **Make batch saves safe to retry.** Reuse the authenticated library add logic and refresh the library once for the batch. Deduplicate selected entries by BoardGameGeek ID before saving. Return per-item outcomes and retry unsuccessful items safely after disconnects or timeouts. The library already guards uniqueness by `(user_id, game_id)`. The shared catalog uses a non-unique `bgg_id` index, so audit legacy duplicates and make creation of a canonical shared row concurrency-safe before enabling parallel saves. Start with serialized saves in the spike. If timings justify it, add a bounded batch endpoint that shares the same write logic and can group metadata fetches. [Add function](../supabase/functions/add-game-to-library/index.ts), [Library schema](../supabase/migrations/20260109190819_001_create_game_tables.sql), [BoardGameGeek ID index](../supabase/migrations/20260201123523_add_bgg_id_to_shared_games.sql)
4. **Handle image lifecycle and release.** Keep images and crops in temporary storage on-device and release them on cancel, retake, or completion. Update the in-app and public privacy copy to describe title and shelf recognition. Record only aggregate timings and outcome counts in beta analytics. Regression-test the one-box title, barcode, and manual search routes. [Privacy copy](../flutter_app/lib/features/privacy/privacy_policy_content.dart), [Public privacy policy](../public/privacy/index.html)

## Decide how many games to support

An initial macOS Apple Vision smoke test used clean, high-contrast synthetic shelf layouts, with a single-line title on each box and varying font sizes. It read 6/6, 10/10, 15/15, and 17/20 titles exactly at both 2,000 and 3,000 px widths. At 2,000 px and the app's default Vision settings, median OCR time across three warm runs per layout ranged from 67 to 78 ms. Lowering Vision's minimum text height to 1% produced the same exact-match counts. This measures raw OCR on one Mac. Launch capacity depends on field photos, mobile-device timings, grouping, catalog lookup, and review and save behavior.

Build a labeled corpus of at least 120 real shelf photos, roughly 30 per test size, with an additional single-box baseline. Label visible boxes, legibility, and expected BoardGameGeek IDs. Include vertically oriented spines, mixed box sizes, glare, stacked boxes, multi-line titles, repeated titles, and base-game and expansion lookalikes. Label obscured and ambiguous boxes so their frequency and handling are visible in the results. Hold out entire shelves during tuning and use the same held-out photos to compare extraction approaches on a lower-end and a recent physical device on each platform.

| Measure | Proposed beta gate |
| --- | --- |
| Recall before edits | At least 90% of legible titles have the correct match presented as a selectable suggestion. Record wrong top matches and missed boxes separately. |
| Precision of preselected matches | At least 95% have the correct BoardGameGeek ID. Track the share of titles preselected so a stricter threshold does not hide extra review work. |
| Time to usable review | p95 within 3 seconds from photo return to an editable list on supported test devices. |
| Time for initial matches | p95 within 15 seconds on a typical connection, measured separately for warm and cold caches. Track upstream requests per photo, throttling, and retries. |
| Time to submit | p95 within 10 seconds for ready entries on a typical connection. Verify safe retries with forced network loss and partial success. |
| End-to-end owner effort | Median time to add the same games at least 30% faster than single add, including fixing or dismissing rows. Track corrections, ignores, and missed-title searches. |

Report the results per batch size, device and platform, including p50/p95 latency, peak memory and error counts. Use the largest size that clears the gates on both platforms under realistic shelf conditions. If recognition degrades first, tighten the capture guidance and support smaller crops. If matching or saving degrades first, prioritize caching and grouped enrichment before increasing the limit.
